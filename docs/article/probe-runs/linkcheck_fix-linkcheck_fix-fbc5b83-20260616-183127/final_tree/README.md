# Link Checker

Утилита для поиска и проверки ссылок в Markdown (`.md`) файлах. Рекурсивно обходит все `.md` файлы в проекте, извлекает из них URL-ссылки и проверяет их доступность через HTTP-запросы.

## Установка

```bash
pip install -e .
```

## Команды

### Извлечение ссылок (`--extract`)

Сканирует все `.md` файлы в проекте и выводит список найденных ссылок для каждого файла.

```bash
python link_checker.py --extract
```

Пример вывода:

```
# README.md
  https://example.com
  https://python.org

# docs/guide.md
  https://docs.python.org/3/
  ./local-file.md
```

### Проверка ссылок (`--check`)

Для каждой найденной ссылки выполняет HTTP-запрос (HEAD, при ошибке — GET) и сообщает о доступности.

```bash
python link_checker.py --check
```

Пример вывода:

```
  ✓ README.md:3  https://python.org  →  200 OK
  ✗ README.md:5  https://example.com/404  →  404 Not Found
  ✗ docs/guide.md:10  https://does.not.exist  →  ConnectionError (нет соединения)
  ✓ docs/guide.md:12  ./local-file.md  →  файл найден
```

## Формат вывода

- **Извлечение** (`--extract`): для каждого файла выводится его путь и список ссылок (по одной на строке с отступом).
- **Проверка** (`--check`): каждая ссылка на отдельной строке. Префикс `✓` — ссылка доступна, `✗` — битая ссылка. Формат: `префикс файл:строка ссылка → статус`.
- **Ошибки**: при недоступности ссылки выводится HTTP-код (404, 500) или тип исключения (ConnectionError, Timeout, SSLError).

## Поведение `--check` в деталях

- Для каждой HTTP/HTTPS ссылки сначала выполняется **HEAD-запрос**. Если сервер не поддерживает HEAD (код 405 или 501), автоматически делается **GET-запрос**.
- **Локальные/относительные** ссылки проверяются на существование файла относительно расположения `.md` файла.
- **Якоря** (`#section`) отбрасываются перед запросом — проверяется только URL без якоря.
- **mailto:**, **tel:**, **ftp:** и прочие не-HTTP схемы пропускаются без проверки.
- Ссылки проверяются **последовательно** — каждая следующая ждёт завершения предыдущей.
- Таймаут одного запроса — **10 секунд**.
- Единая HTTP-сессия (переиспользование соединений) с User-Agent `link-checker/0.1`.

### Известные проблемы

- **Зависание на больших директориях.** Команда `--check` выполняет HTTP-запросы последовательно, без rate limiting. На десятках/сотнях ссылок это приводит к неоправданно долгому выполнению и может выглядеть как зависание. Исправление: добавить ограничение частоты запросов (semaphore / фиксированная задержка) или перейти на асинхронные запросы.

## Обработка ошибок

- При недоступности сервера или таймауте ссылка считается битой, в отчёте указывается тип ошибки.
- Если не удаётся установить соединение с сервером, утилита переходит к следующей ссылке без остановки всего сканирования.
- При ошибке чтения `.md` файла (OSError, UnicodeDecodeError) выводится предупреждение в stderr, файл пропускается.

## Требования

- Python ≥ 3.11
- Зависимости: `requests`, `beautifulsoup4`, `markdown` (будут установлены при `pip install -e .`)
